## مجلد `app/`

### `app/inference.py`

يفصل منطق الذكاء الاصطناعي عن الواجهة:
- `load_model`: يحمّل YOLO checkpoint مرة واحدة.
- `run_image`: يشغّل التنبؤ على صورة ويرجع الصورة المعلّمة والعدادات والجدول.
- `run_video`: يقرأ الفيديو، يأخذ كل Nth frame، يشغّل الموديل، ويكتب فيديو مع Bounding Boxes.
- `summarize_counts`: يحول عدادات الفئات إلى ملخص PPE واضح.

ملاحظة: عدّ الفيديو Frame-level، وليس عدد أشخاص فريدين. ولم نضف Person Tracking أو ربط مؤكد بين الشخص ومعدات الحماية.

## مجلد `training/`

### `hyperparameters.yaml`

ملف إعدادات مركزي. أهم القيم:
- `epochs: 100`: أقصى عدد Epochs، وليس بالضرورة أن يصل التدريب إليه.
- `patience: 20`: Early Stopping بعد 20 Epoch دون تحسن في Validation Fitness.
- `batch: 4`: نفس Batch لـ Nano وSmall للمقارنة.
- `imgsz: 640`: حجم الإدخال.
- `optimizer: AdamW`: تثبيت نوع Optimizer بدل `auto`.
- `lr0: 0.001`, `lrf: 0.01`: البداية والنسبة النهائية لمعدل التعلم.
- `weight_decay: 0.0005`: Regularization للأوزان التي يطبق عليها Optimizer decay.
- `cos_lr: true`: Cosine learning-rate schedule.
- `close_mosaic: 10`: إغلاق Mosaic في آخر 10 Epochs مجدولة.
- `save_period: 10`: حفظ نسخة دورية كل 10 Epochs.

### `dataset_audit.py`

يفحص البيانات قبل التدريب: الصور التالفة، ملفات Labels الناقصة، أخطاء صيغة Annotation، Class IDs غير صحيحة، صناديق خارج المجال الطبيعي، تكرارات SHA-256، وتوزيع كل فئة. يخرج `dataset_audit.json`, `class_distribution.csv`, `class_distribution.png`, و`annotation_issues.csv`.

### `prepare_holdout.py`

ينشئ تقسيمًا جديدًا من صور الـ 800 الأصلية: جزء للتدريب وجزء Holdout للاختبار النهائي. يحتفظ بالـ 200 الرسمية كـ Validation. يستخدم Iterative Multi-label Stratification عند توفرها، ويستبعد التكرارات المتطابقة بين Train وValidation. يكتب `data.safevision.yaml` و`split_report.json`.

مهم: لا تستخدم Checkpoint قديمًا تم تدريبه على كل 800 صورة لتقييم Holdout مستخرج منها؛ لأنه شاهد هذه الصور سابقًا. الـ Notebook الجديدة تعيد التدريب من أوزان YOLO العامة على الـ Train الجديد.

### `train.py`

سكربت تدريب نموذج واحد باستخدام إعدادات `hyperparameters.yaml`. يحفظ Checkpoints ويأخذ `best.pt` و`last.pt` إلى `models/candidates/` مع Manifest.

### `compare_models.py`

يدرّب YOLO26n وYOLO26s بنفس الإعدادات، ثم يقيس المقاييس العامة ومقاييس كل فئة، وحجم Checkpoint وعدد Parameters والوقت. لا يقيّم على Holdout.

### `evaluate.py`

يقيّم نموذجًا على `val` أو `test`. بعد اختيار النموذج فقط نشغّل `--split test` مرة واحدة. ويحفظ JSON وCSV لكل فئة ورسوم Ultralytics.

### `plot_diagnostics.py`

يقرأ `results.csv` ويرسم Training/Validation losses وPrecision/Recall/mAP حسب الأعمدة الموجودة. يعطي ملاحظة استرشادية عن احتمال Divergence؛ لا يشخّص Overfitting بشكل قطعي.

### `benchmark_inference.py`

يقيس زمن inference لصورة واحدة بعد Warmup على GPU أو CPU. النتيجة خاصة بالجهاز والإصدار وحجم الصورة، وليست FPS عامة.

### `regularization_ablation.py`

تجربة اختيارية تقارن Weight Decay = 0.0 و0.0005 و0.001 مع تثبيت باقي الإعدادات تقريبًا. تشغيلها يحتاج GPU إضافيًا. لا نستخدم Holdout لاختيار قيمة Weight Decay.

## مجلد `notebooks/`

- `SafeVision_Colab_Training_Improved.ipynb`: الدفتر الجديد. - `archive/SafeVision_Colab_Training_Baseline.ipynb`: الدفتر القديم الذي أنتج نتائج Baseline السابقة؛ احتفظنا به كسجل تاريخي ولا تستخدمه للتدريب المحسن.

الدفتر المحسن هو نقطة التشغيل الأساسية للـ Audit، Holdout creation، controlled training، diagnostics، model selection، test، benchmark، وexport.

## مجلد `models/`

- `best.pt`: النموذج النهائي الذي تختاره الـ Notebook الجديدة.
- `candidates/`: نسخ Nano وSmall بعد التدريب، حتى لا نفقد المرشحين أثناء المقارنة.
- `model_manifest.json`: معلومات الموديل المختار وإعدادات الاختيار.

لا ترفع Dataset أو ملفات أوزان كبيرة إلى GitHub إلا بعد مراجعة الحجم والترخيص وسياسة المستودع.

## مجلد `runs/`

مخرجات التجارب:
- `data_audit/`: تحليل البيانات والـ Labels.
- `controlled_comparison/`: نتائج تدريب ومقارنة Nano/Small وValidation.
- `diagnostics/`: منحنيات Loss وMetrics.
- `final_evaluation/`: نتيجة Holdout Test بعد اختيار النموذج.
- `benchmark/`: زمن inference المقاس.
- `regularization_ablation/`: نتائج تجربة Weight Decay الاختيارية.

## مجلد `tests/`

اختبارات بسيطة لقواعد التلخيص وتحويل مسار الصور إلى Labels وقراءة class presence. شغّلها باستخدام:

```bash
python -m pytest -q
```

## التسلسل العملي الكامل

1. ارفع المشروع على Google Drive.
2. افتح Notebook المحسنة.
3. راجع Dataset Audit.

5. درّب Nano وSmall بنفس الإعدادات.
6. راجع Loss curves وPer-class Recall.
7. اختر النموذج على Validation فقط.
8. قيّم النموذج المختار مرة واحدة على Holdout.
9. قِس latency على جهاز التشغيل.
10. نزّل `models/best.pt` وشغّل التطبيق.
11. حدّث التقرير والشرائح بالأرقام الجديدة الحقيقية.
